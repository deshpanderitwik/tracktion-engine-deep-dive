How Tracktion Engine is put together

Twelve diagrams, each 300–600 words of commentary, each built by reading the source. This is a teaching artifact — the goal is that a reader who knows how to code but has never touched a DAW codebase can come away able to sketch the major subsystems of one.

How to read this site

Every diagram uses the same visual grammar. Horizontal swimlanes group related nodes. Boxes are source files or conceptual entities. Edges come in exactly three kinds: solid is a static relationship you can see in the source (an #include or an ownership), dashed is a runtime message across some boundary (a callback, an event, an inter-thread queue), dotted is data flowing across a boundary (audio samples, MIDI events, file bytes). Hover a box for its one-line purpose and a path into the source. Click a box to highlight its dependencies (amber) and dependents (teal). Numbered red circles are flags: a tradeoff worth calling out, an open question, or something I couldn't verify from the source. Click one in the sidebar to see which nodes it applies to. Some diagrams also have flow overlays — toggleable animations that trace a specific user journey across the graph. Those are the teaching device that turns a static map into a story.
